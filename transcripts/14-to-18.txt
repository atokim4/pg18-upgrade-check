== 1. Server and data checksums ==
PG 18 initdb enables data checksums by default. pg_upgrade needs the old and new cluster to match.
If data_checksums is off here, run initdb for 18 with --no-data-checksums
(Docker: POSTGRES_INITDB_ARGS=--no-data-checksums), or turn them on in the old cluster with pg_checksums --enable while it is stopped.
         server_version          | data_checksums |    data_directory     
---------------------------------+----------------+-----------------------
 14.24 (Debian 14.24-1.pgdg12+2) | off            | /tmp/pg18-full/data14


== 2. Roles with MD5 password hashes ==
PG 18 deprecates MD5 passwords: CREATE/ALTER ROLE ... PASSWORD with an MD5 hash now emits a warning
(md5_password_warnings = off silences it). pg_upgrade copies existing MD5 hashes over unchanged.
Move these roles to SCRAM: SET password_encryption = 'scram-sha-256'; then \password <role> (or ALTER ROLE ... PASSWORD).
  rolname   | can_login 
------------+-----------
 legacy_app | t

 password_encryption 
---------------------
 scram-sha-256

== 4. Extended statistics (CREATE STATISTICS) in this database ==
pg_upgrade 18 carries most optimizer statistics over, but not these. ANALYZE their tables after the upgrade:
 schema |    statistics_name     | table_name | kinds | run_after_upgrade  
--------+------------------------+------------+-------+--------------------
 public | customers_city_country | customers  | d,f   | ANALYZE customers;

Each one must be installed for PG 18 on the new server (same or newer version) before pg_upgrade runs.

== 6. Columns using reg* types that pg_upgrade refuses ==
pg_upgrade stops on user columns of these OID-referencing types. Change them to text or oid first.

------------+-------------+------


== 7. Unlogged partitioned tables ==
PG 18 rejects CREATE UNLOGGED TABLE ... PARTITION BY. pg_upgrade and pg_dump 18 bring these parents over as plain tables,
so the upgrade itself is fine; update any migration or setup script that still creates them.

== 8. Inheritance parents (not partitions) ==
In PG 18, VACUUM and ANALYZE on a parent also process its inheritance children. Use VACUUM ONLY / ANALYZE ONLY to keep the old behaviour.
 parent | children 
--------+----------
 events |        1


== 9. Database sizes ==
Dump/restore time grows with size; pg_upgrade --link time mostly does not.

-----------+---------

 postgres  | 8571 kB

== 10. Databases whose default collation provider is not libc ==
PG 18 full text search and pg_trgm use the database collation provider instead of always libc.
For databases listed here, REINDEX full-text-search and pg_trgm indexes after pg_upgrade. PG 14 and older only have libc.
(server is older than 15: every database uses libc, nothing to do)
